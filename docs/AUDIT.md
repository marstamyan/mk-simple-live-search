# Проверка MK Simple Live Search

Дата: **13 ноября 2026**. Исходный репозиторий: [marstamyan/mk-simple-live-search](https://github.com/marstamyan/mk-simple-live-search), исходная ревизия `a69204b`, версия плагина 1.0. Исправленная версия: **1.1.0**.

## Результат

Основная идея плагина рабочая: шорткод выводит поле, JavaScript обращается к REST API, WordPress ищет записи и возвращает ссылки. Переписывать плагин на другой стек не потребовалось. Найдены проблемы в ограничении публичного поиска, обработке запросов и работе интерфейса; они исправлены.

## Что исправлено

| Проблема исходного кода | Изменение |
| --- | --- |
| `posts_per_page=-1` разрешал неограниченную выдачу; ограничения отсутствовали на сервере. | REST API принимает только 1–20 результатов; шорткод ограничивает значение тем же диапазоном. |
| Клиент мог указать произвольный тип записи, включая внутренний или непубличный. | Разрешены только существующие публичные типы, доступные для просмотра и включённые в поиск. Встроенные страницы WordPress также поддерживаются. |
| Не были явно заданы опубликованный статус и исключение паролей. Поведение зависело от контекста пользователя и типа записи. | Только `publish`, без пароля; дополнительная проверка публичности каждой записи перед отправкой ответа. Проверено также от имени администратора. |
| Отсутствовала схема REST-параметров: пустые запросы, массивы, неверные режимы и чрезмерные значения обрабатывались непредсказуемо. | Проверяются типы параметров, длина 3–100 символов Unicode, режим поиска и допустимые типы записей. Неверные запросы получают HTTP 400. |
| Режим `both` фактически включал выдержки, хотя описывался как заголовок и содержимое. | Явно заданы `post_title` и `post_content`; оба отдельных режима проверены. |
| Все шорткоды создавали одинаковые ID; работало только первое поле. | Уникальные ID и независимое состояние каждого поля. |
| Старый ответ мог заменить новый. Таймер продолжал работать после очистки короткого запроса. | Отмена таймеров и запросов, отдельный номер каждого запроса; устаревший ответ игнорируется даже при неработающей отмене. |
| Закрытие результатов во время загрузки могло приводить к некорректному повторному открытию. | Закрытие очищает выдачу, повторный фокус запускает актуальный поиск. Добавлена регрессионная проверка. |
| URL строился добавлением `?query=`, что ломало обычные постоянные ссылки с `?rest_route=`. | Используются `URL` и `searchParams`, сохраняющие существующие параметры. Проверено на реальном сайте с обычными ссылками. |
| Ошибки HTTP могли выглядеть как отсутствие совпадений. | Отдельные состояния загрузки, пустой выдачи и ошибки с возможностью повторить поиск. |
| Не было связанной метки поля и управления результатами с клавиатуры. | Метки, live status, Arrow Up/Down, Enter, Escape и обычный Tab. |
| HTML-сущности заголовков отображались буквально; отсутствовала проверка схем ссылок. | Сервер возвращает обычный текст; клиент использует `textContent` и допускает только HTTP(S)-ссылки. |
| Стили админки подключались на всех административных страницах. | Стили подключаются только на странице инструкции плагина. JavaScript подключается при использовании шорткода. |
| Интерфейс был непереводимым, в инструкции оставалось ограничение «одно поле». | Строки подготовлены к переводу, инструкция и README соответствуют фактическим возможностям. |

Ненужный nonce удалён: публичный endpoint только читает опубликованные общедоступные записи. Само отсутствие nonce у такого endpoint не является ошибкой. Правила публичного endpoint и параметры WordPress сверены с [документацией REST API](https://developer.wordpress.org/rest-api/extending-the-rest-api/routes-and-endpoints/) и [WP_Query](https://developer.wordpress.org/reference/classes/wp_query/).

## Выполненные проверки

- **9 тестов JavaScript**: гонки ответов, отмена таймера, повторный фокус после закрытия, независимость нескольких полей, обычные ссылки WordPress, ошибки HTTP, безопасные ссылки/текст, клавиатура и ввод с композицией символов.
- **44 интеграционные проверки REST API на реальном WordPress 7.1.4 / PHP 8.4.27**: заголовок/текст/выдержка, страницы, пользовательский тип записей, все ограничения параметров, Unicode, лимиты, приватность и отсутствие изменения глобальной записи. Проверки создают временные записи и пользователя, затем удаляют их.
- **15 интеграционных проверок шорткодов** в том же WordPress: уникальные ID, метки, параметры отдельных полей, ограничения, неверный тип записи, подключение ресурсов.
- **Минимальная поддерживаемая связка WordPress 6.2 / PHP 7.4.14** отдельно проверена на второй установке: те же **44 REST + 15 проверок шорткодов прошли**. Подробности — в `artifacts/compatibility-report.md`.
- **20 проверок в настоящем браузере Microsoft Edge через Playwright**: поиск по кириллице, минимум символов, переход по ссылке, клавиатура, несколько полей, режимы поиска, лимит, портфолио, пустая выдача, ошибка HTTP и экран 390 px. Ошибок JavaScript не обнаружено. Результаты и снимки находятся в `artifacts/browser/`.
- Синтаксис всех производственных PHP-файлов проверен PHP 7.4.14. Проверки гонок используют управляемую имитацию DOM/сети; полноценную интеграцию отдельно проверяет настоящий браузер.
- ZIP содержит только установочные файлы внутри каталога `mk-simple-live-search/`; локальная база, тестовые учётные записи и инструменты в него не входят.

## Пределы проверки

Проверка выполнена на отдельных локальных установках, без доступа к рабочему сайту. Основная среда использует SQLite Database Integration; поведение конкретного MySQL/MariaDB-хостинга, большая база и совместимость со всеми сторонними темами/плагинами не проверены. У SQLite поиск по кириллице зависит от регистра иначе, чем у распространённых MySQL collations; демонстрационные тексты используют одинаковый регистр. Сам плагин применяет штатный поиск WordPress.

Это поиск по заголовку и содержимому с подстроками и правилами WordPress. Поиск по произвольным полям, морфология, исправление опечаток и автодополнение слов не реализованы. Запросы ограничены по длине и объёму ответа; отдельного счётчика запросов на IP нет. Для сайта с большим трафиком нагрузку следует оценить на его базе и использовать обычные средства хостинга/CDN.

Готовность к работе с клавиатурой проверена; отдельного испытания с NVDA/JAWS и полной сертификации доступности не проводилось. Строки готовы к переводу; комплект переводов не входит в эту версию.

## Использование результатов

Установочный архив: `artifacts/mk-simple-live-search-1.1.0.zip`. Для повторной сборки: `powershell -File scripts/build-release.ps1`.

Учебное видео подготовлено из настоящих действий в локальном WordPress. Последний вариант — с английскими пояснениями, без озвучки: `artifacts/mk-simple-live-search-english-silent.mp4`. Исходники записи и монтажа находятся в `demo/`; готовые MP4 остаются локальными файлами.

Код, тесты и инструкции подготовлены для репозитория. Установка на рабочий сайт в рамках этой проверки не выполнялась. Тестовая база, локальные инструменты и готовые видео исключены из Git.
